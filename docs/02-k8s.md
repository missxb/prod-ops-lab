## 1. 阶段目标

完成企业级 Kubernetes 集群的搭建与配置，包括：
- Master 节点初始化（高可用架构）
- Worker 节点加入集群
- 网络插件部署（Calico）
- CoreDNS 配置优化
- 集群安全策略配置
- 网络策略（NetworkPolicy）初始设置
- 集群自愈能力验证

## 2. 架构说明

```
                    ┌─────────────────────────────────────────────┐
                    │              Kubernetes 集群架构              │
                    ├─────────────────────────────────────────────┤
                    │                                             │
                    │   ┌─────────┐  ┌─────────┐  ┌─────────┐    │
                    │   │ Master1 │  │ Master2 │  │ Master3 │    │
                    │   │ (HA)    │◄─┤ (HA)    │◄─┤ (HA)    │    │
                    │   └────┬────┘  └────┬────┘  └────┬────┘    │
                    │        │            │            │          │
                    │   ┌────┴────────────┴────────────┴────┐     │
                    │   │     etcd 集群 (3节点)              │     │
                    │   └───────────────────────────────────┘     │
                    │                                             │
                    │   ┌─────────┐  ┌─────────┐  ┌─────────┐    │
                    │   │ Worker1 │  │ Worker2 │  │ Worker3 │    │
                    │   └─────────┘  └─────────┘  └─────────┘    │
                    │                                             │
                    │   Calico CNI (BGP/VXLAN)                    │
                    │   CoreDNS (DNS服务)                          │
                    │   Metrics Server (指标采集)                   │
                    └─────────────────────────────────────────────┘
```

### 高可用架构说明
- **3 Master 节点**：避免单点故障，支持滚动更新
- **3 etcd 节点**：保证数据一致性，容忍1个节点故障
- **负载均衡器**：分发 API Server 请求，支持健康检查
- **Calico 网络**：支持 NetworkPolicy，BGP 或 VXLAN 模式

### 集群规格建议
| 组件 | 最低规格 | 推荐规格 |
|------|---------|---------|
| Master | 4C/8GB | 8C/16GB |
| Worker | 4C/8GB | 8C/32GB |
| etcd | 2C/4GB | 4C/8GB |
| 网络带宽 | 1Gbps | 10Gbps |

## 3. 前置条件

- 阶段1（基础环境初始化）已完成
- 所有节点已安装 kubeadm、kubelet、kubectl
- 所有节点 containerd 已配置并运行
- Swap 已关闭
- 网络互通，防火墙已配置
- 至少 3 个 Master 节点（高可用）或 1 个 Master 节点（测试）
- Load Balancer 已配置（高可用方案）

## 4. 详细步骤

### 4.1 初始化 Master 节点（第一个节点）

#### 4.1.1 创建 kubeadm 配置文件

```yaml
# kubeadm-config.yaml
# 该文件定义集群初始化的所有参数
apiVersion: kubeadm.k8s.io/v1beta3
kind: InitConfiguration
localAPIEndpoint:
  advertiseAddress: 172.16.0.11  # Master 节点管理网络 IP
  bindPort: 6443
nodeRegistration:
  criSocket: unix:///run/containerd/containerd.sock
  imagePullPolicy: IfNotPresent
---
apiVersion: kubeadm.k8s.io/v1beta3
kind: ClusterConfiguration
# 集群版本 —— 确保所有节点版本一致
kubernetesVersion: v1.29.0
# 集群名称 —— 用于区分不同环境
clusterName: enterprise-cloud
# 控制面端点 —— HA 场景使用 LB 地址
controlPlaneEndpoint: "172.16.0.10:6443"
# etcd 配置
etcd:
  local:
    dataDir: /var/lib/etcd
    # 外部 etcd 时使用 external 配置
networking:
  # Pod 网络 CIDR —— Calico 默认使用此网段
  podSubnet: "192.168.0.0/16"
  # Service 网络 CIDR —— 集群内部服务发现
  serviceSubnet: "10.96.0.0/12"
  dnsDomain: "cluster.local"
# API Server 额外参数
apiServer:
  extraArgs:
    # 启用审计日志
    audit-log-path: /var/log/kubernetes/audit.log
    audit-log-maxage: "30"
    audit-log-maxsize: "100"
    audit-log-maxbackup: "3"
    # 启用加密
    encryption-provider-config: /etc/kubernetes/encryption-config.yaml
    # 请求超时
    request-timeout: "300s"
  extraVolumes:
    - name: audit-log
      hostPath: /var/log/kubernetes
      mountPath: /var/log/kubernetes
      readOnly: false
# Controller Manager 配置
controllerManager:
  extraArgs:
    # 指定 node-cidr-mask-size
    node-cidr-mask-size: "24"
    # 启用 Leader Election
    leader-elect: "true"
# Scheduler 配置
scheduler:
  extraArgs:
    leader-elect: "true"
---
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
# cgroup 驱动 —— 必须与 containerd 一致
cgroupDriver: systemd
# 容器运行时
containerRuntimeEndpoint: unix:///run/containerd/containerd.sock
# DNS 配置
clusterDNS:
  - 10.96.0.10
clusterDomain: cluster.local
# 资源管理
evictionHard:
  memory.available: "500Mi"
  nodefs.available: "10%"
  nodefs.inodesFree: "5%"
# 日志配置
containerLogMaxSize: "50Mi"
containerLogMaxFiles: 5
```

#### 4.1.2 创建必要目录

```bash
# 创建审计日志目录
mkdir -p /var/log/kubernetes
# 创建 etcd 数据目录
mkdir -p /var/lib/etcd
# 设置权限 —— etcd 对数据目录权限敏感
chmod 700 /var/lib/etcd
```

#### 4.1.3 创建加密配置文件

```yaml
# /etc/kubernetes/encryption-config.yaml
# 用于加密 Secret 资源，保护敏感数据
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
      - secrets
    providers:
      - aescbc:
          keys:
            - name: key1
              secret: <base64编码的32字节密钥>
      - identity: {}  # 回退到明文读取旧数据
```

#### 4.1.4 初始化第一个 Master

```bash
# 预拉取镜像 —— 加速初始化过程
# 使用国内镜像源
kubeadm config images pull \
    --image-repository registry.aliyuncs.com/google_containers \
    --kubernetes-version v1.29.0

# 初始化集群
kubeadm init --config=kubeadm-config.yaml \
    --upload-certs \
    --v=5

# --upload-certs: 将控制面证书上传到 Secret，方便后续节点加入
# --v=5: 详细日志级别，便于排查问题
```

#### 4.1.5 配置 kubectl

```bash
# 为当前用户配置 kubeconfig
# 这样 kubectl 就能访问集群
mkdir -p $HOME/.kube
cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
chown $(id -u):$(id -g) $HOME/.kube/config

# 验证集群状态
kubectl get nodes
# NAME     STATUS     ROLES           AGE   VERSION
# node-1   NotReady   control-plane   1m    v1.29.0
# 节点状态为 NotReady 是因为网络插件尚未安装，属正常现象

kubectl get pods -A
# 查看所有系统 Pod 运行状态
# kube-system namespace 下应有 API Server、etcd、scheduler 等运行中
```

### 4.2 安装 Calico 网络插件

#### 4.2.1 安装 Calico

```bash
# Calico 是最流行的 K8s 网络插件之一
# 支持 NetworkPolicy，提供 BGP 和 VXLAN 两种模式
# BGP 适合大规模集群，VXLAN 适合云环境

# 安装 Calico operator
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.27.0/manifests/tigera-operator.yaml

# 等待 operator 就绪
kubectl wait --for=condition=Available deployment/tigera-operator \
    -n tigera-operator --timeout=300s

# 创建 Calico 自定义资源
cat << 'EOF' | kubectl apply -f -
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    # 指定 Pod CIDR —— 必须与 kubeadm-config.yaml 中一致
    ipPools:
      - name: default-ipv4-ippool
        blockSize: 26
        cidr: 192.168.0.0/16
        encapsulation: VXLANCrossSubnet
        natOutgoing: Enabled
        nodeSelector: all()
    # 使用 BGP 模式（可选）
    # bgp: Disabled
---
apiVersion: operator.tigera.io/v1
kind: APIServer
metadata:
  name: default
spec: {}
EOF

# 等待 Calico Pod 就绪
kubectl -n calico-system rollout status daemonset/calico-node --timeout=300s

# 验证 Calico 安装
kubectl get pods -n calico-system
# NAME                                       READY   STATUS    RESTARTS   AGE
# calico-kube-controllers-5f8b9b6d4b-xxxxx   1/1     Running   0          5m
# calico-node-xxxxx                          1/1     Running   0          5m

# 检查 Calico Felix 状态
kubectl -n calico-system exec -it <calico-node-pod> -- calico-node status
```

### 4.3 加入 Worker 节点

#### 4.3.1 获取 join 命令

```bash
# 在 Master 节点执行，获取 Worker 加入命令
# 初始化完成后会输出 join 命令，也可以重新生成
kubeadm token create --print-join-command

# 输出示例：
# kubeadm join 172.16.0.10:6443 --token abc123.def456 \
#     --discovery-token-ca-cert-hash sha256:xxxxxx
```

#### 4.3.2 Worker 节点加入集群

```bash
# 在每个 Worker 节点执行（node-2, node-3）
kubeadm join 172.16.0.10:6443 \
    --token <token> \
    --discovery-token-ca-cert-hash sha256:<hash>

# 对于 Control Plane 节点加入，需要额外参数
kubeadm join 172.16.0.10:6443 \
    --token <token> \
    --discovery-token-ca-cert-hash sha256:<hash> \
    --control-plane \
    --certificate-key <cert-key>
```

#### 4.3.3 验证节点状态

```bash
# 在 Master 节点执行
kubectl get nodes -o wide
# NAME     STATUS   ROLES           AGE   VERSION   INTERNAL-IP   ...
# node-1   Ready    control-plane   10m   v1.29.0   172.16.0.11   ...
# node-2   Ready    <none>          5m    v1.29.0   172.16.0.12   ...
# node-3   Ready    <none>          3m    v1.29.0   172.16.0.13   ...

# 等待所有节点 Ready（可能需要 1-2 分钟）
kubectl wait --for=condition=Ready node/node-2 --timeout=120s
kubectl wait --for=condition=Ready node/node-3 --timeout=120s
```

### 4.5 配置集群自愈能力

#### 4.5.1 配置 Pod 污点容忍

```bash
# 容忍控制平面节点的 NoSchedule 污点
# 这允许系统 Pod 调度到 Master 节点
kubectl taint nodes node-1 node-role.kubernetes.io/control-plane:NoSchedule- || true
```

#### 4.5.2 配置节点自动伸缩（可选）

```bash
# 安装 Cluster Autoscaler —— 根据负载自动增减节点
# 注意：需要云平台 API 支持
cat << 'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cluster-autoscaler
  namespace: kube-system
  labels:
    app: cluster-autoscaler
spec:
  replicas: 1
  selector:
    matchLabels:
      app: cluster-autoscaler
  template:
    metadata:
      labels:
        app: cluster-autoscaler
    spec:
      serviceAccountName: cluster-autoscaler
      containers:
        - name: cluster-autoscaler
          image: k8s.gcr.io/autoscaling/cluster-autoscaler:v1.29.0
          command:
            - ./cluster-autoscaler
            - --v=4
            - --stderrthreshold=info
            - --cloud-provider=aws
            - --skip-nodes-with-local-storage=false
            - --expander=least-waste
            - --node-group-auto-discovery=asg:tag=k8s.io/cluster-autoscaler/enabled,k8s.io/cluster-autoscaler/enterprise-cloud
            - --balance-similar-node-groups
            - --skip-nodes-with-system-pods=false
EOF
```

### 4.6 配置集群备份

```bash
# 安装 etcd 备份脚本
cat > /usr/local/bin/etcd-backup.sh << 'SCRIPT'
#!/bin/bash
# etcd 定期备份脚本
# 建议 cron 每天执行一次

BACKUP_DIR="/backup/etcd/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BACKUP_DIR"

# 备份 etcd 数据
ETCDCTL_API=3 etcdctl snapshot save "$BACKUP_DIR/snapshot.db" \
    --endpoints=https://127.0.0.1:2379 \
    --cacert=/etc/kubernetes/pki/etcd/ca.crt \
    --cert=/etc/kubernetes/pki/etcd/healthcheck-client.crt \
    --key=/etc/kubernetes/pki/etcd/healthcheck-client.key

# 验证备份
ETCDCTL_API=3 etcdctl snapshot status "$BACKUP_DIR/snapshot.db" \
    --write-table

# 保留最近 30 天的备份
find /backup/etcd -maxdepth 1 -type d -mtime +30 -exec rm -rf {} \;

echo "备份完成: $BACKUP_DIR"
SCRIPT

chmod +x /usr/local/bin/etcd-backup.sh

# 添加 cron 定时任务
echo "0 2 * * * /usr/local/bin/etcd-backup.sh >> /var/log/etcd-backup.log 2>&1" | crontab -
```

## 6. 常见问题

### Q1: 节点一直显示 NotReady
**原因**：网络插件未正确安装
**解决**：
```bash
# 检查 Calico Pod 状态
kubectl get pods -n calico-system
kubectl describe pod <calico-pod> -n calico-system

# 检查节点日志
journalctl -u kubelet -n 100 | grep -i error

# 重启 kubelet
systemctl restart kubelet
```

### Q2: etcd 同步异常
**原因**：网络延迟或时钟不同步
**解决**：
```bash
# 检查 etcd 集群状态
ETCDCTL_API=3 etcdctl member list \
    --endpoints=https://127.0.0.1:2379 \
    --cacert=/etc/kubernetes/pki/etcd/ca.crt \
    --cert=/etc/kubernetes/pki/etcd/healthcheck-client.crt \
    --key=/etc/kubernetes/pki/etcd/healthcheck-client.key

# 检查时间同步
chronyc tracking

# 重启 etcd
systemctl restart etcd
```

### Q3: Pod 无法调度
**原因**：资源不足或节点污点
**解决**：
```bash
# 查看调度失败原因
kubectl describe pod <pod-name>
# 查看 Events 部分

# 检查资源请求
kubectl describe node <node-name> | grep -A 10 "Allocated resources"

# 检查节点污点
kubectl describe node <node-name> | grep -A 5 Taints
```

### Q4: kubectl 命令超时
**原因**：API Server 不可达
**解决**：
```bash
# 检查 API Server 状态
curl -k https://172.16.0.10:6443/healthz

# 检查 kubeconfig
kubectl config view

# 检查网络连通性
ping 172.16.0.10
telnet 172.16.0.10 6443

# 检查防火墙规则
iptables -L -n | grep 6443
```

### Q5: CoreDNS 解析失败
**原因**：CoreDNS Pod 异常或配置错误
**解决**：
```bash
# 检查 CoreDNS Pod
kubectl -n kube-system get pods -l k8s-app=kube-dns
kubectl -n kube-system logs <coredns-pod>

# 重启 CoreDNS
kubectl -n kube-system rollout restart deployment/coredns
```

## 7. 回滚方案

### 7.1 完全重置集群

```bash
# 在所有节点执行
kubeadm reset -f

# 清理 iptables 规则
iptables -F && iptables -X
iptables -t nat -F && iptables -t nat -X
iptables -t mangle -F && iptables -t mangle -X
iptables -t raw -F && iptables -t raw -X

# 清理 IPVS 规则
ipvsadm --clear

# 清理 CNI 配置
rm -rf /etc/cni/net.d/

# 清理 kubeconfig
rm -rf $HOME/.kube/config
rm -rf /etc/kubernetes/

# 清理 etcd 数据
rm -rf /var/lib/etcd/

# 重启 containerd
systemctl restart containerd
```

### 7.2 重置单个 Worker 节点

```bash
# 在需要重置的 Worker 节点执行
kubeadm reset -f

# 在 Master 节点移除该节点
kubectl delete node <node-name>

# 清理 Worker 节点的 iptables 和 CNI
iptables -F && iptables -X
rm -rf /etc/cni/net.d/
systemctl restart containerd

# 重新加入集群
kubeadm join ...
```

### 7.3 紧急恢复 etcd

```bash
# 如果 etcd 集群多数节点故障，使用备份恢复
# 1. 停止所有 etcd
systemctl stop etcd

# 2. 恢复数据
ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd/snapshot.db \
    --data-dir=/var/lib/etcd-restored

# 3. 更新 etcd 配置指向新数据目录
# 4. 启动 etcd
systemctl start etcd

# 5. 验证
ETCDCTL_API=3 etcdctl member list
```

## 8. 最佳实践

1. **高可用架构**：生产环境至少 3 Master 节点 + 外部负载均衡器
2. **网络规划**：
   - Pod CIDR 使用 /16，支持 65536 个 Pod
   - Service CIDR 使用 /12，支持 4096 个 Service
   - 避免与现有网络冲突
3. **版本管理**：
   - Master 和 Worker 使用相同 K8s 版本
   - 升级前在测试环境验证
   - 逐节点升级，先 Worker 后 Master
4. **安全配置**：
   - 启用 etcd 加密
   - 配置审计日志
   - 使用 RBAC 控制权限
   - 定期轮换证书（kubeadm certs renew）
5. **监控与告警**：
   - 部署 Prometheus + Grafana 监控集群指标
   - 配置关键指标告警（CPU、内存、Pod 状态）
6. **备份策略**：
   - 每天自动备份 etcd 数据
   - 保留 30 天备份
   - 定期测试恢复流程
7. **文档维护**：
   - 记录所有自定义配置
   - 维护操作手册
   - 定期审查和更新文档
8. **测试验证**：
   - 部署后进行完整功能测试
   - 验证故障恢复能力
   - 压力测试集群性能
