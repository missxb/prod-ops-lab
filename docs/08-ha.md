# 高可用架构详细文档

## 1. 概述

本阶段部署完整的高可用架构，包括：
- Keepalived: VIP漂移
- Nginx: 负载均衡
- MySQL: 主从复制
- Redis: Sentinel集群

## 2. Keepalived配置

### 2.1 架构说明

```
Keepalived高可用架构：

┌─────────────────────────────────────────────────────────────┐
│                    Keepalived集群                           │
├─────────────────────────────────────────────────────────────┤
│  Master节点 (192.168.1.20)                                 │
│  ├── VIP: 192.168.1.100                                    │
│  ├── 优先级: 101                                           │
│  └── 状态: MASTER                                          │
├─────────────────────────────────────────────────────────────┤
│  Backup节点 (192.168.1.21)                                 │
│  ├── VIP: 无                                               │
│  ├── 优先级: 100                                           │
│  └── 状态: BACKUP                                          │
├─────────────────────────────────────────────────────────────┤
│  健康检查                                                   │
│  ├── 检查Nginx进程                                          │
│  ├── 检查网络连通性                                         │
│  └── 故障时VIP漂移                                         │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 部署Keepalived

```bash
# 安装Keepalived
yum install -y keepalived

# 复制配置
cp configs/keepalived/keepalived-master.conf /etc/keepalived/keepalived.conf

# 启动服务
systemctl enable keepalived
systemctl start keepalived
```

### 2.3 配置说明

**Master配置：**
```conf
vrrp_script check_nginx {
    script "/etc/keepalived/check_nginx.sh"
    interval 2
    weight -20
}

vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 101
    advert_int 1
    
    authentication {
        auth_type PASS
        auth_pass 1111
    }
    
    virtual_ipaddress {
        192.168.1.100/24
    }
    
    track_script {
        check_nginx
    }
}
```

### 2.4 验证Keepalived

```bash
# 检查VIP
ip addr show | grep 192.168.1.100

# 检查状态
systemctl status keepalived

# 测试漂移
systemctl stop keepalived
# 在Backup节点检查VIP
```

## 3. Nginx负载均衡

### 3.1 架构说明

```
Nginx负载均衡架构：

┌─────────────────────────────────────────────────────────────┐
│                    Nginx LB                                 │
├─────────────────────────────────────────────────────────────┤
│  上游服务器 (upstream)                                      │
│  ├── K8s Master 1: 192.168.1.10:6443                       │
│  ├── K8s Master 2: 192.168.1.11:6443                       │
│  └── K8s Master 3: 192.168.1.12:6443                       │
├─────────────────────────────────────────────────────────────┤
│  负载均衡算法                                               │
│  ├── 轮询 (round-robin)                                    │
│  ├── 加权轮询 (weighted)                                   │
│  └── IP哈希 (ip_hash)                                      │
├─────────────────────────────────────────────────────────────┤
│  健康检查                                                   │
│  ├── 被动检查 (max_fails + fail_timeout)                   │
│  └── 主动检查 (health_check)                               │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 部署Nginx

```bash
# 安装Nginx
yum install -y nginx

# 复制配置
cp configs/nginx/nginx-lb.conf /etc/nginx/nginx.conf

# 测试配置
nginx -t

# 启动服务
systemctl enable nginx
systemctl start nginx
```

### 3.3 配置说明

```nginx
upstream k8s_api {
    least_conn;
    server 192.168.1.10:6443 weight=5 max_fails=3 fail_timeout=30s;
    server 192.168.1.11:6443 weight=5 max_fails=3 fail_timeout=30s;
    server 192.168.1.12:6443 weight=5 max_fails=3 fail_timeout=30s;
    
    keepalive 32;
}

server {
    listen 6443 ssl;
    server_name k8s-api.example.com;
    
    ssl_certificate /etc/nginx/ssl/server.crt;
    ssl_certificate_key /etc/nginx/ssl/server.key;
    
    location / {
        proxy_pass https://k8s_api;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_connect_timeout 10s;
        proxy_read_timeout 300s;
    }
}
```

### 3.4 验证Nginx

```bash
# 测试配置
nginx -t

# 检查状态
systemctl status nginx

# 测试访问
curl -k https://192.168.1.100:6443/version
```

## 4. MySQL主从复制

### 4.1 架构说明

```
MySQL主从复制架构：

┌─────────────────────────────────────────────────────────────┐
│                    MySQL HA                                 │
├─────────────────────────────────────────────────────────────┤
│  Master (192.168.1.30)                                     │
│  ├── Server ID: 1                                          │
│  ├── Binlog: 启用                                          │
│  ├── 半同步复制: 启用                                       │
│  └── GTID: 启用                                            │
├─────────────────────────────────────────────────────────────┤
│  Slave (192.168.1.31)                                      │
│  ├── Server ID: 2                                          │
│  ├── Relay Log: 启用                                       │
│  ├── 只读模式: 启用                                        │
│  └── IO/SQL Thread: 运行                                   │
├─────────────────────────────────────────────────────────────┤
│  复制方式                                                   │
│  ├── 异步复制 (默认)                                       │
│  ├── 半同步复制 (推荐)                                     │
│  └── GTID复制 (推荐)                                       │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 部署MySQL

```bash
# 安装MySQL
yum install -y mysql-server

# 复制配置
cp configs/mysql/master.cnf /etc/my.cnf

# 启动服务
systemctl enable mysqld
systemctl start mysqld

# 配置复制
CHANGE MASTER TO
    MASTER_HOST='192.168.1.30',
    MASTER_USER='repl_user',
    MASTER_PASSWORD='repl_pass',
    MASTER_AUTO_POSITION=1;
```

### 4.3 配置说明

**Master配置：**
```ini
[mysqld]
server-id = 1
log-bin = mysql-bin
binlog-format = ROW
gtid-mode = ON
enforce-gtid-consistency = ON
```

**Slave配置：**
```ini
[mysqld]
server-id = 2
relay-log = relay-bin
read-only = ON
super-read-only = ON
gtid-mode = ON
enforce-gtid-consistency = ON
```

### 4.4 验证MySQL

```bash
# 检查主从状态
mysql -e "SHOW MASTER STATUS\G"
mysql -e "SHOW SLAVE STATUS\G"

# 测试复制
# 在Master创建表
mysql -e "CREATE DATABASE test; USE test; CREATE TABLE t1 (id INT);"
# 在Slave检查
mysql -e "SHOW DATABASES;"
```

## 5. Redis Sentinel

### 5.1 架构说明

```
Redis Sentinel架构：

┌─────────────────────────────────────────────────────────────┐
│                    Redis Sentinel                           │
├─────────────────────────────────────────────────────────────┤
│  Sentinel节点 (3个)                                        │
│  ├── 监控Master状态                                        │
│  ├── 故障检测                                               │
│  └── 自动故障转移                                          │
├─────────────────────────────────────────────────────────────┤
│  Redis Master (1个)                                        │
│  ├── 写入节点                                               │
│  └── 数据源                                                │
├─────────────────────────────────────────────────────────────┤
│  Redis Slave (2个)                                         │
│  ├── 读取节点                                               │
│  └── 数据副本                                               │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 部署Redis

```bash
# 安装Redis
yum install -y redis

# 复制配置
cp configs/redis/redis-master.conf /etc/redis/redis.conf

# 启动服务
systemctl enable redis
systemctl start redis

# 启动Sentinel
redis-sentinel /etc/redis/sentinel.conf
```

### 5.3 配置说明

**Master配置：**
```conf
# redis.conf
bind 0.0.0.0
port 6379
daemonize yes
requirepass redis_pass
masterauth redis_pass

# 持久化
save 900 1
save 300 10
save 60 10000

appendonly yes
appendfsync everysec
```

**Sentinel配置：**
```conf
# sentinel.conf
port 26379
sentinel monitor mymaster 192.168.1.30 6379 2
sentinel down-after-milliseconds mymaster 5000
sentinel failover-timeout mymaster 10000
sentinel parallel-syncs mymaster 1
```

### 5.4 验证Redis

```bash
# 检查Master状态
redis-cli -h 192.168.1.30 INFO replication

# 检查Sentinel状态
redis-cli -h 192.168.1.30 -p 26379 SENTINEL masters

# 测试故障转移
redis-cli -h 192.168.1.30 DEBUG sleep 10
# 检查新的Master
redis-cli -h 192.168.1.31 INFO replication
```

## 6. 故障转移测试

### 6.1 测试方法

```bash

# 检查VIP是否漂移到Backup

systemctl stop nginx
# 检查服务是否中断

# 测试MySQL
# 停止Master
systemctl stop mysqld
# 检查Slave是否提升为Master

# 测试Redis
# 停止Master
redis-cli -h 192.168.1.30 DEBUG sleep 10
# 检查Sentinel是否故障转移
```

### 6.2 验证检查

```bash
# Keepalived
ip addr show | grep 192.168.1.100

# Nginx
curl -k https://192.168.1.100:6443/version

mysql -h 192.168.1.100 -u root -p -e "SHOW MASTER STATUS"

redis-cli -h 192.168.1.100 -p 26379 SENTINEL get-master-addr-by-name mymaster
```

## 7. 常见问题

### 7.1 VIP无法漂移

```bash
# 检查防火墙
firewall-cmd --list-all
# VRRP协议需要允许

# 检查网络
ping 192.168.1.100

# 检查Keepalived日志
journalctl -u keepalived -f
```

### 7.2 MySQL复制延迟

```bash
# 检查复制状态
mysql -e "SHOW SLAVE STATUS\G"

# 检查网络延迟
ping 192.168.1.30

# 检查大事务
mysql -e "SHOW PROCESSLIST"
```

### 7.3 Redis Sentinel故障转移失败

```bash
# 检查Sentinel日志
tail -f /var/log/redis/sentinel.log

# 检查网络
ping 192.168.1.30

# 检查配置
cat /etc/redis/sentinel.conf
```

## 8. 最佳实践

1. **非抢占模式**: 避免VIP频繁漂移
2. **健康检查**: 配置完善的健康检查脚本
3. **监控告警**: 监控VIP状态和复制延迟
4. **备份策略**: 定期备份MySQL和Redis数据
5. **容量规划**: 预留足够的资源应对故障转移
